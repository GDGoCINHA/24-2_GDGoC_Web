# 산출물 수명 — 무엇을 레포에 남기나

레포에 남아야 하는 건 **작업이 끝난 뒤에 제대로 쓴 최종본**이다.
작업 중의 조사 메모·중간 JSON·대조 리포트는 그 작업에서만 쓰인다.

## 어디에 쓰나 — 읽는 주체로 가른다

| 누가 읽나 | 어디 | 예 |
|---|---|---|
| 제품 코드·CI·DB | 소유 모듈 안 | `src/main/resources/**` · `src/main/resources/db/migration/*.sql` |
| 이 과제를 모르는 사람이 **결론으로** | `docs/<주제>.md` — 최종본 | `docs/ARCHITECTURE.md` · `docs/ADR.md` |
| **작업 중의 나·에이전트만** | `.claude/work/<과제>/` | 조사 메모 · 중간 산출물 · 일회성 스크립트 |

**세 번째가 기본값이다.** 위 둘 중 하나라고 말할 수 있을 때만 레포에 쓴다.

## 과제 이름은 브랜치에서 나온다

```
feature/eventboard          →  .claude/work/eventboard/
fix/deploy-image-prune      →  .claude/work/deploy-image-prune/
```

`feature/`·`fix/`·`chore/` 접두사를 떼고 나머지를 쓴다. 없으면 만든다.

**레지스트리를 따로 두지 않는 이유:** 손으로 관리하는 목록은 반드시 낡는다.
git 은 이미 지금 어느 과제인지 알고 있고, 그 사실은 틀리지 않는다.

## 두 개의 시점

| | 신호 | 하는 일 |
|---|---|---|
| **승격** | PR 을 올리기 직전 | `work/` 에서 레포에 남길 것을 판정해 `docs/<주제>.md` 로 쓰고 기존 문서에 엮는다 |
| **회수** | 브랜치가 `develop` 에 머지됨 | `work/<과제>/` → `.claude/attic/<과제>/` 로 **옮긴다** |

승격이 머지 **전**이어야 하는 이유는 단순하다 — 최종본은 커밋되어야 한다.

회수 트리거를 만료일이 아니라 머지에 거는 이유: **날짜는 틀리지만 머지는 사실이다.**
`git branch --merged develop` 이 답을 갖고 있다.

회수는 삭제가 아니다. `.claude/` 는 git 추적 밖이라 삭제가 되돌려지지 않고,
되돌릴 수 없으면 무서워서 아무도 안 치운다. attic 은 로드되지 않으므로 남겨두는 대가가 0이다.

## 최종본 자립 조건

작업 공간은 버려진다. 그러므로 **최종본만으로 재현 가능해야 한다.** 셋을 담는다.

1. **근거** — 각 주장에 출처. 공식 문서 URL 이나 `file:line`
2. **판정 사유** — 왜 이 값인가. 결론만 있으면 다음 사람이 같은 조사를 다시 한다
3. **재생성 방법** — 중간물이 다시 필요할 때 어떻게 만드는지 한 줄

**이 셋이 없는 최종본은 작업 공간을 못 버린다.** 그때는 버리지 말고 최종본을 먼저 고친다.

## 스냅샷 문서

특정 시점의 조사 결과는 제목 바로 아래에 배너를 단다.

```markdown
> ⏱ **스냅샷 2026-08-04** — 그 시점의 조사 결과다. 이후 변경은 반영되지 않는다.
```

배너 없는 스냅샷은 정본으로 오독된다. **최종 수정일은 신선도의 증거가 아니다.**

## 정리하기 전에

문서를 옮기거나 지우기 전에 **역참조를 확인한다.** 문서를 붙잡는 건 대개 코드·CI·정책 파일이다.

```bash
git grep -n -F "docs/<파일명>"
```

살아 있는 코드가 가리키고 있으면 옮기지 않는다. **역참조가 신선도의 증거다.**
`.github/workflows/` 가 경로나 본문을 붙잡고 있으면 그 문서는 계약이다.
